# SPARK Growth Lab — Full-Stack Project

A student-first growth experiment prototype with a responsive frontend, FastAPI backend, and SQLite database.

## Features

- Interactive rule-based project matchmaker.
- Demo workshop registration form saved to SQLite.
- UTM campaign link builder and copyable message template.
- Event/funnel tracker with demo, target, and observed record types.
- Dashboard metrics that count **only observed** visits/registrations as measured campaign outcomes.
- CSV export.
- A/B experiment log with hypothesis, variants, status, winner, and notes.
- API documentation generated by FastAPI.
- Accessible navigation, keyboard focus, responsive layout, and reduced-motion support.

## Requirements

- Python 3.10 or newer (3.11 recommended)
- Internet connection only for installing packages; the app itself can run locally offline after installation.

## Run on Windows

1. Extract the ZIP.
2. Open the extracted `SPARK_FullStack` folder.
3. Open Command Prompt or PowerShell in that folder.
4. Create a virtual environment:

   ```powershell
   py -m venv .venv
   .\.venv\Scripts\Activate.ps1
   ```

   If PowerShell blocks activation, use Command Prompt and run:
   ```bat
   .venv\Scripts\activate.bat
   ```

5. Install dependencies:
   ```powershell
   pip install -r backend/requirements.txt
   ```
6. Start the application:
   ```powershell
   python -m uvicorn backend.main:app --reload
   ```
7. Open **http://127.0.0.1:8000**.
8. API documentation: **http://127.0.0.1:8000/docs**.
9. Health check: **http://127.0.0.1:8000/api/health**.

The SQLite database is created automatically at `backend/spark.db` on first start. A clearly labelled illustrative demo event is inserted if the event table is empty.

## Important limitations and safety

- This is a demonstration project, not a production service.
- Registration is a local demo form. It does not send emails, verify identity, handle payments, or connect to NxtWave systems.
- Use test emails only. Do not enter sensitive personal information.
- The app has no authentication. Anyone who can reach the server may read/write demo data. Do not expose it publicly as-is.
- CORS is permissive for local demonstration. Restrict it before production deployment.
- SQLite is appropriate for a small local demo, not high-volume concurrent production traffic.
- Project suggestions are deterministic rules, not generated by a live AI model.
- The UTM builder creates tags; a real analytics tool or server-side attribution pipeline is not integrated.
- The seed record is `demo`, never a claim of actual campaign performance.
- Before any real campaign, replace example destinations with approved URLs and obtain permission for outreach channels.

## Core API routes

| Method | Route | Purpose |
|---|---|---|
| GET | `/api/health` | Service status |
| GET | `/api/dashboard` | Event ledger and observed-only totals |
| POST | `/api/events` | Add a funnel record |
| DELETE | `/api/events/{id}` | Delete an event |
| GET | `/api/events/export` | Export rows for CSV download |
| GET | `/api/experiments` | List experiments |
| POST | `/api/experiments` | Create an experiment |
| PATCH | `/api/experiments/{id}` | Update an experiment |
| DELETE | `/api/experiments/{id}` | Delete an experiment |
| POST | `/api/registrations` | Save a demo workshop registration |
| GET | `/api/registrations/count` | Count demo registrations |

## Demo walkthrough (3–4 minutes)

1. Start at the hero and explain the hypothesis: a project preview may reduce uncertainty for beginners.
2. Change the interests and generate a project idea. Explain that it uses transparent rules, not a live LLM.
3. Create a campaign link and explain `utm_source`, `utm_medium`, `utm_campaign`, and `utm_content`.
4. Submit a test registration using a test email.
5. Add an event record labelled `demo`; refresh the dashboard and export CSV.
6. Create an A/B experiment. Explain that you would not declare a winner until there is comparable exposure and enough evidence.
7. Open `/docs` and show the API routes.
8. Be clear that all sample records are illustrative and no real campaign has run.

## Reset demo data

Stop the server, then delete `backend/spark.db`. Restart the server to create a fresh database and illustrative seed record. Do not delete the database while the app is running.
